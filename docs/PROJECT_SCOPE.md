# 个人学习与知识管理助手

本项目基于 [DeerFlow](https://github.com/bytedance/deer-flow) 二次开发。保留原许可证、版权声明和提交历史。本文描述目标范围，不代表功能已经实现。

## 项目目标

面向个人用户，构建能执行基础文件整理、管理学习资料并提供基于资料的学习辅导的助手。用户通过自然语言提出需求，系统调用工具执行，保存过程和结果，并允许用户逐项验证。

核心目标：

1. 在 Windows 授权目录中真实完成新建文件夹、文件重命名和分类操作。
2. 支持资料导入、更新、删除与来源查看，形成可维护的个人知识库。
3. 实现完整 RAG 管线：解析、切分、向量化、检索、上下文组装和带引用回答。
4. 根据用户基础、学习目标和可用时间制定可编辑的学习计划，结合选定资料进行讲解、举例与练习。
5. 持久保存学习进度、用户确认的笔记、错题和复习记录，后续可继续学习和检索。
6. 形成可运行的演示、自动测试和效果评测，明确上游能力与本项目新增贡献。

端到端验收场景：用户要求整理 Redis 学习资料，确认整理方案后执行，导入所选资料并建立索引；根据 Java 基础制定学习计划，开始一个章节，完成练习，确认保存笔记和错题；重启后仍能查看资料、进度和记录。

## 项目约束

### 产品与范围

- 第一版按单用户、本地使用设计，不承诺多用户共享与跨设备同步。
- 默认使用 Windows 本地文件服务，DeerFlow 使用 Docker 运行；两者通过受控接口或 MCP 连接。
- 文件操作限定于用户明确选择的授权目录。桌面等目录也必须加入授权范围，不以模型猜测的路径执行。
- 第一版资料格式限定为文本型 PDF、Markdown、TXT；扫描件 OCR、音视频解析与其他格式另行规划。
- 资料来自用户上传、授权目录中选定的文件或用户提供的文字。自动联网搜集资料不属于第一版必需能力。
- 第一版不提供任意 Shell、桌面点击自动化、付款、外部消息发送、主动删除原文件、外部通知和复杂多 Agent 调度。

### 文件执行

- 原始资料默认保留；新建目录是可直接执行的基础操作，批量重命名、分类移动先展示方案并等待确认。
- 确认绑定具体操作方案。路径、目标或操作内容变化后，原确认失效。
- 授权检查在本地服务执行端实施；规范化路径，并处理路径穿越、符号链接和 Windows junction 导致的越界。
- 不静默覆盖同名文件，冲突应明确展示并提供可选择的处理方式。
- 执行前核对源文件状态；文件在预览后变化时停止相关操作并提示重新规划。
- 保存逐项执行记录，以实际文件状态验证成功；重试前核对已有结果，避免重复执行。
- 撤销限定于有记录且满足状态检查的移动、重命名操作。文件被后续修改或路径冲突时不得强行覆盖。

### 知识库与 RAG

- 原始文件、文档元数据和索引各有明确存储位置；用稳定文档 ID 关联，不仅依赖文件路径。
- 保留文档来源、版本和片段定位信息；有页码时保留页码，不生成不存在的定位信息。
- 文档更新或删除后同步处理检索索引。删除知识库记录不默认删除原始文件。
- 检索限定于用户当前选定的知识库；已有上游 RAG 接口是否满足写入和管理需求，需要实际检查。
- 检索到的资料作为数据处理，不能覆盖用户指令或执行权限。资料中的指令不能自动触发本地操作。
- 回答引用必须对应本次实际检索到的片段。资料不足时明确说明；使用模型常识补充时标明依据类型。
- 原始资料、用户笔记与助手生成内容分别标记。助手生成笔记经用户确认后入库，不能把全部聊天自动作为可信资料。
- 先建立基础检索与评测基线，再依据结果决定是否增加混合检索、查询改写或重排。

### 学习与数据

- 学习计划、章节进度、练习结果和复习日期保存为结构化数据，不仅保存在聊天上下文中。
- 学习计划可编辑、暂停和继续，重启后进度应保留。
- 学习掌握程度结合答题结果和用户反馈；阅读过讲解不能自动等同于掌握。
- 主观题提供参考反馈，不将模型评分视为绝对正确；复习日期用于应用内展示，第一版不承诺推送提醒。
- API Key、本地配置、用户文件、知识库数据和执行日志不提交 Git；调用外部模型或 embedding 服务时，明确哪些内容需要发送到服务商。
- 本地执行服务采用身份校验和有限工具接口，不直接开放无需认证的本机控制端点。

### 工程与开发流程

- 优先复用 DeerFlow 基础能力，以扩展实现业务逻辑；修改核心前说明现有接口不足之处。
- 不删除或修改无关模块，不重写整个框架；保留许可证、版权声明和来源说明。
- 任务记录关联框架 thread/run，明确状态来源，避免两套运行状态互相冲突。
- 每项能力按“开发 → 必要自动测试 → 用户验证 → 修复 → 下一项”推进。
- 每次交付提供启动方式、测试输入、预期结果和已知限制；涉及重启或配置变更时明确说明。
- 功能完成以真实工具执行和验收结果为准，不以模型声称成功或界面展示成功为准。
- 开发不自动等同于提交、推送或发布；当前任务未明确授权时，不执行这些动作。
- 不预设提升百分比或编造实验数据；评测使用固定资料、问题、模型配置与预算，记录失败案例。

## 分阶段验收

| 阶段 | 用户验证方式 | 完成标准 |
| --- | --- | --- |
| 本地服务连通 | 在聊天中要求在授权目录创建测试文件夹 | 文件夹真实存在，返回实际路径；越界请求被拒绝 |
| 文件整理 | 对测试文件生成分类和命名预览，确认后执行并撤销 | 预览与执行一致，无静默覆盖；符合条件的操作可恢复 |
| 知识库管理 | 导入、重复导入、更新和删除文档 | 状态明确，版本与来源可查看，新查询不检索已删除内容 |
| RAG | 提问有答案、无答案及跨片段问题，查看引用 | 相关片段可找到，引用支持结论，无依据不编造 |
| 学习计划 | 输入目标、基础和时间，修改计划并重启 | 计划可执行、可编辑，进度持久化 |
| 讲解与练习 | 开始章节并回答题目 | 内容关联选定资料，答题反馈及学习记录可查看 |
| 笔记与复习 | 确认笔记入库，保存错题并重新练习 | 内容可检索、编辑与删除，复习记录持久化 |
| 整体验收 | 执行完整 Redis 学习场景，并模拟工具失败 | 完整流程可重复，失败说明准确，恢复不会重复修改文件 |

## 第一版范围

- Windows 本地文件服务：授权目录、新建文件夹、分类、重命名、操作预览、执行记录及有条件撤销。
- 知识库管理：PDF、Markdown、TXT 导入，来源记录，重复检查、更新与删除。
- RAG：文档切分、向量化、检索、上下文组装、带引用回答及效果评测。
- 学习：学习计划、章节讲解、练习、持久化进度。
- 沉淀：确认后保存笔记、错题和复习记录。
